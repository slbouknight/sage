# 0018: stb_image for decoding, and an authored test texture

**Status:** Accepted

**Context:** M4 needs PNG bytes turned into texels. fastgltf's
`LoadExternalImages` reads image files into memory but explicitly does not decode
them, so a decoder is required. Separately,
[ADR 0014](0014-vendor-a-cc0-test-asset.md) deliberately omitted Lantern's four
texture PNGs — the `.glb` bundle would have been 9.5 MB — which left M4 with a
model that has `TEXCOORD_0` on every primitive and no image to put on it.

**Decision:** Add `stb` (MIT OR CC-PDDC) for decode, included as a **system**
include directory. That is not cosmetic: stb's implementation block trips
`-Wold-style-cast` and `-Wconversion` by the dozen, and `-isystem` silences
warnings originating inside the header without weakening a single flag for our
own code. `STB_IMAGE_IMPLEMENTATION` is defined in `texture.cpp` alone, which is
also the only translation unit including the header — wrapped in
`// clang-format off`, because `IncludeBlocks: Regroup` otherwise sorts the
include away from the `#define` that configures it. Rather than re-vendoring
Khronos artwork, the test texture is generated by `tools/make_uv_grid.py` into
`assets/uv_grid.png`: 4.3 KB, and reproducible from source rather than committed
as opaque bytes. Its pattern is chosen to fail loudly — a red block at UV (0,0)
and green at (1,0) make a flipped V axis obvious rather than merely suspicious,
and one-pixel grid lines shimmer visibly if mip selection is wrong.

**Consequences:** `stbi_load` is called with `STBI_rgb_alpha`, which is
mandatory rather than convenient: `R8G8B8_SRGB` reports *no* optimal-tiling
features on any of the three drivers present on the development machine, so
three-channel images are not sampleable at all. The reported
`channels_in_file` therefore says 3 for this asset while the data in memory is
RGBA — the two are unrelated numbers. A grid is not a base-colour map, so the
glTF material path still has nothing real to load; restoring Lantern's own
textures, or vendoring a smaller textured asset, is a decision deferred to the
materials work. stb decodes PNG and JPEG only, so KTX2 or basis-compressed
textures would need a different library.
