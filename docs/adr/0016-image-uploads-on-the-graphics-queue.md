# 0016: Image uploads run entirely on the graphics queue

**Status:** Accepted

**Context:** [ADR 0010](0010-synchronous-staging-uploads-with-queue-ownership-transfer.md)
puts buffer uploads on the transfer queue and hands ownership to graphics
afterwards. The obvious move was to reuse that shape for images. It does not
work: mip levels are generated by successive `vkCmdBlitImage`, and the Vulkan
registry declares that command `queues="VK_QUEUE_GRAPHICS_BIT"` — the
transfer-only family (family 1 on this hardware) physically cannot record it.
The alternative, copying on transfer and then transferring ownership so graphics
can blit, keeps the letter of ADR 0010 while adding an ownership dance around a
chain that has to run on graphics regardless.

**Decision:** `Uploader::upload_to_image` records everything on the graphics
queue in one command buffer: transition all levels `UNDEFINED` →
`TRANSFER_DST`, copy the staging buffer into level 0, then for each level flip
its predecessor to `TRANSFER_SRC` and blit it halved with `VK_FILTER_LINEAR`,
and finally transition every level to `SHADER_READ_ONLY_OPTIMAL`. Only one queue
family ever touches the image, so there is no ownership transfer at all — the
image path is *simpler* than the buffer path, not more complex. Each level blits
from the level above rather than from level 0, because `VK_FILTER_LINEAR` samples
a 2x2 neighbourhood regardless of reduction factor: a direct 512→8 blit would
read four texels and discard the rest. The rule is now "buffers use the transfer
queue, images do not", and it follows from a queue capability rather than taste.

**Consequences:** Startup-only and fully synchronous, matching ADR 0010's
ergonomics — every upload stalls the graphics queue and allocates a fresh
staging buffer. The final transition needs two subresource ranges, because
levels 0..n-2 end in `TRANSFER_SRC` while the last was only ever written and
sits in `TRANSFER_DST`; the single-level case has no first range at all.
`BLIT_SRC`, `BLIT_DST` and `SAMPLED_IMAGE_FILTER_LINEAR` are per-format,
per-driver guarantees rather than universal ones, so `Texture` asserts on them
instead of assuming. Offline-generated mips (KTX2, or a compute downsampler)
would replace the blit chain and remove the graphics-queue constraint entirely,
which is the version this gets rewritten into if streaming ever matters.
